# SSCPay 付款侧与收款侧插件安装指南

本文的「本站」指 **SSCPay 订单平台**。先看顾客在哪一步访问你的网站：**选商品、提交订单的是商城站；打开付款链接、实际完成支付的是网关站**。付款侧装网关插件（也叫「收款站聚合插件」），商户收款侧装商城插件。本指南适用于 PayPal、信用卡等法币支付，不适用于链上收款。

## 配置速查：两端分别要拿什么

| 你负责哪一端 | 从 SSCPay 平台领取 | 由这一端提供给 SSCPay |
| --- | --- | --- |
| **付款侧 · 网关站**（WordPress + WooCommerce） | ① 公开网关主包 `sscpay-gateway-aggregator.zip`；② 平台运维私下交付的初始化包 `sscpay-gateway-site-setup.zip`，用于写入默认回调密钥。**不用领 App-ID、API Key 或更新令牌。** | 网关站的 HTTPS 根地址，以及该站 WooCommerce 签发的**读写** Consumer Key（CK）和 Consumer Secret（CS）。可直接授权回填，不用把密钥发给别人。 |
| **商户收款侧 · 商城站**（WooCommerce 或 OpenCart） | ① 对应的商城插件；② 商户 API 的 HTTPS 根地址；③ 本应用的 `App-ID`；④ 配套的 `API Key`；⑤ 商户的支付组标识 `group_key`。只有指定固定渠道时才另领 `payment_method_key`。 | 提供商城域名，用于平台登记应用。支付通知和顾客回跳地址由插件随订单自动发送；只有启用物流回传时，才另把插件显示的物流接收地址填回平台应用。 |

只负责商城结账的商户可直接看「商城站」一节，**不需要私有初始化包、网关站的 CK / CS，也不需要第三方通道密钥**。开装前确认站点支持 HTTPS；网关站在 WordPress「设置 → 固定链接」确认不是「朴素」格式。WooCommerce 的[官方图文说明](https://woocommerce.com/document/woocommerce-rest-api/)列出了固定链接要求和生成 CK / CS 的操作。

## 付款侧：安装网关站插件

1. **拿两个包。** 在 SSCPay 后台「支付配置 → 支付方式 → 创建或编辑」右上角点 **下载网关插件**；已发布的主包也可从平台 HTTPS 域名下的 `/plugins/gateway/download` 免登录下载。私有初始化包不在下载中心，请向平台运维领取对应环境的包。私有 ZIP 等同于回调凭证，不要放在网站公开目录、群聊或工单里。
2. **在实际网关站启用。** 先启用 WooCommerce，在 WordPress「插件 → 安装插件 → 上传插件」上传私有初始化 ZIP，点 **立即安装 → 启用插件**，再安装并启用公开网关主包。**旧站升级不要先删除旧主插件**：先备份数据库和 WordPress 安全盐，在旧版主插件仍启用时激活初始化包，再覆盖升级主包。多站点须在对应子站逐站激活，不要全网启用。
3. **确认回调密钥。** 到网关站「支付网关聚合 → 设置 → 出站回调签名密钥」，看到 **已配置，不显示现有密钥** 即表示本站能读取密钥。确认后只停用并删除**私有初始化插件**，保留主插件。不用改 `wp-config.php`。公开主包默认从 `https://www.ssecurepay.com` 更新，无需令牌；如使用自有更新源，点「修改更新域名」，填可信的 HTTPS 域名。**更新域名不是商城 API 地址。**
4. **让平台能连接网关站。** 在 SSCPay「支付配置 → 支付方式」创建或编辑**法币**支付方式，「网站域名」填网关站的 HTTPS 根地址（不是商城域名，也不带 `/wp-json`）。点 **WordPress 授权获取 CK / CS**，在新标签页用该网关站管理员账号批准读写权限，回到原窗口确认已回填。若手工操作：到**网关站**「WooCommerce → 设置 → 高级 → REST API → 添加密钥」，选有 WooCommerce 管理权限的用户和**读/写**权限，把生成的 `ck_…`、`cs_…` 分别填回平台的 **Consumer Key（CK）**、**Consumer Secret（CS）**。手工生成的 CS 离开页面后不能再次查看。
5. **接通实际支付通道。** 在网关站「支付网关聚合 → 设置 → 本站 Webhook 地址」复制对应通道的地址，按通道要求到 Stripe、PayPal 等后台登记。第三方账号凭证和 Webhook 验签信息由**通道方**提供，在 **SSCPay 支付方式 → 网关配置**选择相应配置模板并填写，不填到商城插件。保存支付方式，确认提示已同步；如仅显示「已保存，同步电商网站失败」，修正后点 **同步支付配置**。成功时平台自动记录支付配置 ID，不用手填。按组路由时，把已启用且该商户可用的渠道加入其支付组。

**三个通知不要配反：** ① Stripe、PayPal → 网关站：在通道后台登记网关站显示的 Webhook URL，验签用通道方提供的资料（如 Stripe 的签名密钥、PayPal 的 Webhook ID）；② 网关站 → SSCPay：平台下单时自动给出 `callback_url`，用私有初始化包设置的回调密钥签名；③ SSCPay → 商城：商城插件下单时自动给出 `notify_url`，用商城应用的 `API Key` 验签。后两项都不用手填通知地址。

## 收款侧：安装商城站插件

先让有权限的管理员在 SSCPay 后台取值。测试和正式环境要分别确认，**不要用正式通道凭证做沙箱测试**。

| 商城插件要填的字段 | 在 SSCPay 哪里拿、怎么填 |
| --- | --- |
| **API Base URL / API 根地址** | 向平台管理员确认本环境的**商户 API 域名**。例如接口为 `https://api.example.com/api/order/create`，这里只填 `https://api.example.com`，不加 `/api`、`/admin` 或接口路径。域名是示例，不是固定值。 |
| **App-ID、API Key** | 「商户配置 → 应用 → 查看 → API 凭证」，从**同一个已启用的应用**复制 `App ID` 和 `API Key`；没有应用先创建，官网域名填商城站。有权限的管理员可以再次查看，无须为复制而重新生成。没有权限请联系该商户管理员。 |
| **支付组 `group_key`** | 「支付配置 → 支付组」，复制本商户已启用支付组的 **组标识**，不是显示名称或数字 ID。即使指定固定渠道也要填，不要照抄插件的示例值。 |
| **指定渠道 `payment_method_key`（选填）** | 仅在平台要求固定渠道时，从「支付配置 → 支付方式」复制该渠道的 **标识**（`method_code`）。按支付组分配时**留空**；WooCommerce 版可能已预填 `paypal` 或 `creditcard`，应清空后保存。固定渠道要求商城的通知、返回、取消三个地址与渠道绑定站点同域；商城与网关分属不同域名时应使用组路由。 |

### WooCommerce 商城

1. 从 SSCPay 首页「插件下载」（`/plugins`）选 WordPress，按需下载 `sscpay-payment-paypal`、`sscpay-payment-creditcard`。在商城 WordPress 后台上传 ZIP 并启用；需要两种付款方式就分别安装、分别配置。
2. 到「WooCommerce → 设置 → 付款 → SSCPay - PayPal / SSCPay - 信用卡」。先用沙箱：勾选「沙箱模式」，把上表的地址、App-ID、API Key 填进**沙箱环境**栏，再填支付组和可选渠道。平台标识保留 `wordpress`；多家商城共用一个商户时，为各站设置不同的商户订单号前缀。
3. 勾选「启用」，保存，到商城结账页确认已出现该方式。上线时先填好**生产环境**的地址和凭证，再关闭沙箱模式并保存。

### OpenCart 商城

1. 在同一下载中心选择与商城大版本匹配的包。3.x 下载 `sscpay-opencart3.ocmod.zip`；4.x 下载 `sscpay.ocmod.zip`，**不要改文件名**。在「扩展 → 安装器」上传；4.x 上传后还要点该包的安装按钮。
2. 在「扩展 → 扩展 → 支付」分别安装、编辑所需的 SSCPay PayPal / Credit Card。每种方式单独填写上表信息，平台标识用 `opencart`。这里没有 WooCommerce 式的两套环境栏，先在测试商城填测试凭证，勿在已有订单的店铺来回切换环境。
3. 配置订单状态映射：只有「全额付款」映射到商城的处理中／完成类状态，部分付款和失败不能映射为已付。启用并保存。

## 验收：用一笔沙箱订单核对结果

用测试商城、平台测试应用和支付通道沙箱，从商城结账走一遍。**顾客看到成功页不等于到账**，要核对以下三个地方：

| 检查点 | 应看到什么 | 不符合时先查什么 |
| --- | --- | --- |
| 商城 → SSCPay | 平台能按商户订单号找到订单，顾客拿到付款链接 | 找不到订单：核对 API 根地址、环境、App-ID / API Key；出现 `PAYMENT_METHOD_DOMAIN_MISMATCH` 则查是否误填了固定渠道。 |
| SSCPay → 网关站 | 付款链接打开正确网关站的收银台 | 核对支付方式的**网关站**域名、CK / CS 读写权限、支付配置同步结果，以及支付组中是否有已启用的可用渠道。 |
| 支付通道 → 网关站 → SSCPay → 商城 | 沙箱付款后，平台订单已付款，商城订单也随之更新 | 平台未更新：先查通道 Webhook 是否送达网关站，再查「支付网关聚合 → 日志」和出站回调密钥。平台已付但商城未更新：查平台订单详情的通知记录，以及商城的支付日志、通知地址和应用凭证。 |

## 排查：回调密钥未配置或无法读取

1. **确认是同一站点。** 在实际收款的网关站查看 WordPress 插件列表；只上传初始化 ZIP 不会写入密钥，必须启用它。多站点要检查对应子站。
2. **确认激活流程已执行。** 如果只是覆盖了已启用的初始化插件，只停用并重新启用**初始化插件**，再刷新主插件设置。看到「已配置，不显示现有密钥」后，可停用并删除初始化插件。
3. **检查是否保存过自定义值。** 自定义密钥优先于默认值。若迁站或安全盐变化使它不可读，重复初始化不会覆盖它。请平台运维核对后，在「修改回调密钥」录入与本环境平台一致的值。不要删除主插件、重置安全盐或把密钥贴到聊天中。
