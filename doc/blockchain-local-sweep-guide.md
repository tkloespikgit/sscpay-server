# 本地钱包归集操作教程

整理日期：2026-11-11。适用资产：BTC、LTC、ETH、USDT-ERC20、USDT-TRC20。

**状态：自研本地工具的操作流程设计稿，工具尚未实现或通过资金测试。** 本文中的“查询余额”“生成归集计划”等为拟定功能名称，不是现有软件的真实菜单。当前不能按本文在系统中点击执行；工具交付时须补齐版本、实际界面、截图和逐链测试结果。总体规则见[区块链收款方案](../docs/blockchain-payment-plan.md)。

本教程按链和资产区分，不要求为每种资产安装不同品牌钱包。目标是使用一个本地工具，在操作者设备上管理地址、签名和广播。服务器与 Tatum 都不接收钱包私钥；Tatum 只提供公开链数据、行情或已签名交易的节点广播能力。

交付形式已确定为管理后台独立的“资金归集教程”网页，供商户按资产与环境逐步操作；本文件作为网页教程的内容依据，实际页面尚未开发。页面入口、图文、下载、地址导出权限和密钥输入边界见[方案第 10.5 节](../docs/blockchain-payment-plan.md)。网页只提供指引，所有钱包解锁和签名在本地工具完成。

## 1. 所有资产共用的准备步骤

### 1.1 收款钱包与只读绑定

1. 在经过验证的本地工具中创建专用收款钱包，或导入兼容的专用钱包；按实际格式选择助记词、加密钱包文件或硬件签名设备。
2. 备份恢复资料。若使用助记词附加口令，必须同时备份并区分“附加口令”和软件解锁密码。
3. 导出只读绑定包：网络、派生方案、扩展公钥、派生源指纹、版本和核对地址。平台不接收助记词、扩展私钥、私钥、带密钥的钱包文件或密码。
4. 在支付方式配置中导入只读资料，核对多个派生地址一致后再启用。普通收款地址不能替代扩展公钥。
5. 各网络先在测试环境验证地址可恢复、可转出，再做受控的小额主网验收。测试与正式钱包分开。

兼容的钱包格式和派生路径须由工具版本明确列出；不能声称所有 BIP39 钱包、imToken 或硬件钱包都可无缝导出公钥和访问海量地址。一个单地址 Keystore 不等于整个 HD 钱包。

### 1.2 开始一次归集

1. 从平台导出自己有权操作的地址清单，包含网络、资产、地址、派生路径和索引、只读源指纹及配置版本，不含密钥。
2. 导入本地工具；工具本地重新派生并比对来源地址，失败则停止。
3. 配置链上数据连接。默认接入 Tatum 时使用操作者自己的 API 凭证，不使用打包在软件中的平台共享密钥；测试网和主网不能混用。
4. 在本地解锁专用收款钱包。工具不会把解密资料发送给平台或 Tatum。
5. 选择资产、来源地址范围和最低归集阈值，查询当前余额及未完成交易。
6. 填写并独立核对归集目标网络与地址。首次使用目标地址先做一小批试归集，成功后再操作其余地址。

已完成的订单、过期订单地址均可能有余额。工具读取链上实际资产，不把订单净入账当作钱包可转出额，也不自动扣取平台服务费；月度费用按业务约定线下缴纳。

### 1.3 统一预览和结果保存

确认前至少展示：来源网络与地址、资产合约、计划数量、目标地址、费用资产、预计费用与上限、找零或剩余处理方式，以及本次是否包括手续费补充。

执行后保存不含密钥的任务文件：任务 ID、来源地址、交易哈希、nonce 或输入 UTXO、处理阶段、目标、数量、实际费用和错误。归集不会自动扣减商户平台账面余额。若本次实际用于履行取款，另在平台取款申请中提交证据并按审核流程核销。

网络超时、窗口关闭、软件重启均先恢复原任务并查询交易，不重新生成同一笔转出。只有明确知道旧交易状态和替换关系时，才允许加速或重建。

## 2. BTC 钱包归集

### 2.1 需要准备

- Bitcoin 网络的专用钱包、完整地址／索引资料。
- 明确支持 Bitcoin 主网的目标地址，测试时改用对应测试网目标。
- 已确认且未花费的收款输出。通常手续费直接从本次 BTC 输入中支付，无需向每个地址另补手续费币。

### 2.2 操作步骤

1. 选择 BTC 和正确网络，导入地址范围，执行“查询可用 UTXO”。
2. 查看每笔输出的数量、确认数及是否已被其他待处理任务占用；排除未确认、冲突和已花费项。
3. 选择归集 UTXO。输入数量过多时分批；小额输出预计手续费超过其价值时先跳过。
4. 填归集目标，选择费率或费用上限。费率与交易体积有关，不按“来源地址数乘固定费用”报价。
5. 查看预览：输入总额、目标到账数量、预计费用、找零。全额归集通常以输入总额减实际交易费用作为目标数量；若产生找零，其地址必须由本地钱包验证。
6. 本地确认并签名。工具可使用 PSBT 等经验证的交易格式，不能把签名请求简化成看不懂的任意哈希授权。
7. 广播后等待确认，记录 txid、实际手续费及目标到账结果。
8. 完成后刷新来源 UTXO，核对已花费状态；不能把找零或内部归集再次算作订单收入。

### 2.3 常见问题

- **某输入已经被花费**：停止当前计划，查询其他任务和链上结果，再重建剩余输入，不能重复广播不同归集交易抢同一输入。
- **费用高、交易未确认**：保留原任务，按钱包和交易能力选择经过验证的加速方式，不承诺所有交易都能替换。
- **钱包恢复后少地址**：使用平台导出的派生范围恢复，处理 gap limit，不能只看默认扫描到的几个地址。

签名分离的参考：[Electrum 离线签名流程](https://electrum.readthedocs.io/en/latest/coldstorage.html)。这不表示必须安装 Electrum，也不表示 Electrum 已完成与本系统的兼容测试。

### 2.4 BTC 怎么测试（含 Tatum 监听）

1. 先按[方案第 13.1 节](../docs/blockchain-payment-plan.md)查 Tatum 实际支持的测试通知网络；Bitcoin Testnet 的代际必须明确，不能领取 Testnet4 币却订阅另一个 Testnet。
2. 在该网络创建独立的测试发送钱包、收款派生钱包及归集目标，领取同网络测试 BTC；将公钥资料绑定到测试支付方式。
3. 为订单派生两个地址 A、B，分别建立可用通知订阅。从发送钱包向 A 付足订单，另向 B 分两笔补足，记录各次 txid／vout。
4. 验证每笔真实回调签名、输出位置与确认数；B 未付足前不入账，付足后每订单只入一次。重复回调不重复增加测试余额。
5. 把 A、B 导入本地工具，查询实际 UTXO，先归集一小批，再用多输入交易转到测试目标。核对输入总额 = 目标输出＋找零＋网络费。
6. 关闭工具后恢复原任务，确认已花费输入不会再次被使用；归集完成不改变平台原订单净入账。
7. 在本地 Regtest 另测冲突、重组与受控出块；Testnet4／Signet 的 Tatum RPC 测试也单独记录，不把 RPC 成功等同通知成功。

通过条件：网络一致、真实通知可收到且验签通过、所有输出正确归单、只入账一次、归集与恢复无重复花费。若目标测试网没有 Tatum 通知能力，明确该项未通过，改用其支持的测试网联调，不能省略监听验收。

## 3. LTC 钱包归集

### 3.1 需要准备

- Litecoin 专用钱包与地址／索引资料；不能将 Bitcoin 的网络参数和手续费规则直接套用。
- 支持 Litecoin 网络的目标地址。本期仅处理工具明确支持的普通透明地址，不包含未适配的 MWEB 资金。
- 已确认未花费输出，手续费使用 LTC。

### 3.2 操作步骤

1. 在工具中明确选择 LTC／Litecoin 网络，查询来源地址的 UTXO。
2. 本地核对派生地址和网络参数，排除已花费、冲突或被其他任务占用的输入。
3. 选择来源输出及分批大小；工具按 Litecoin 当前费率重新估算，不能复制 BTC 的费用值。
4. 填写 LTC 目标地址，检查归集数量、费用、粉尘输出和找零地址。
5. 先确认一笔小批量计划，本地签名、广播并等待确认。
6. 核对目标收到的是 LTC 后，再执行余下批次并保存交易清单。
7. 刷新来源已花费状态，导出结果，归集本身不改平台账面余额。

### 3.3 常见问题

输入被占用、交易卡住和钱包恢复缺地址，按照 BTC 一节的同类原则处理，但必须使用 Litecoin 交易与费率。不要为方便恢复而安装停止维护、来源未核验的钱包版本。客户端和网络实现参考 [Litecoin 官方项目](https://github.com/litecoin-project/litecoin)，具体兼容版本随工具交付确定。

### 3.4 LTC 怎么测试（含 Tatum 监听）

1. 使用 Litecoin Testnet，分别核实 Tatum 的测试 RPC 和 Notifications 事件类型。用测试资料创建发送、派生收款和归集目标钱包，不复用 BTC 钱包网络参数。
2. 获取测试 LTC。先用 RPC／浏览器核对发送钱包所在网络，再向平台生成的两个普通透明地址转入测试款。
3. 核对通知签名、txid／vout、LTC 最小单位及确认状态；至少覆盖一笔多输出转账和一笔少付后补款。
4. 本地工具选择这批已确认 UTXO，估算 LTC 费率、预览并签名归集；在同一 Litecoin Testnet 查询目标到账和找零。
5. 模拟工具中断后恢复、重复通知和重复扫描；平台净额不能因归集重复增加。手续费高于小额输出价值时应提示跳过。
6. 用 Litecoin Regtest 单独做双花、重组和已花费输入冲突；该结果不等于 Tatum 公共测试网联调结果。

通过条件：收到真实 LTC 测试通知、输出正确匹配、手续费单位与网络无混用、本地归集成功且账本不重复。MWEB 不在本期测试通过范围。

## 4. ETH 钱包归集

### 4.1 需要准备

- Ethereum 专用 HD 钱包和可访问的派生索引。
- Ethereum 主网目标地址；测试使用 Sepolia 等明确配置的网络。
- 各来源地址已有 ETH，可以从自身余额支付手续费；过小余额可能不值得转出。

### 4.2 操作步骤

1. 选择 ETH，查询来源地址的当前余额和未确认交易，核对 chain ID。
2. 填目标地址及每笔／本批费用上限。默认使用普通收款地址；若目标是合约地址，必须模拟和估算其执行要求，不能一概当作固定 Gas。
3. 工具逐地址计算可转出额：余额减去需要预留的最大手续费；不足以覆盖费用的地址跳过。
4. 预览来源、目标、可转出额、nonce、费用上限和预计剩余 ETH；不能只展示多个地址的合计数。
5. 操作者确认整批计划，本地逐笔签名并有界并发广播。多个来源地址通常仍是多笔链上交易，不是一次免 Gas 的批量转账。
6. 逐笔查询成功回执并等确认；失败项保留状态，不自动重发新的转账。
7. 查询来源剩余 ETH。由于预留费用与实际费用不同，可能有少量余额；仅在经济合理时安排二次归集，不承诺一次精确清零。

### 4.3 常见问题

- **交易 pending**：查询原 hash、来源 nonce 和其他待处理任务；需要加速时保持同一逻辑交易和可追踪替换关系。
- **费用超过上限**：等待或由操作者重新确认新计划，不自动突破限制。
- **目标地址回执失败**：记录实际消耗的 Gas，重新核对目标类型与原因；失败交易不表示本金已到目标。

Ethereum 费用依据见[官方 Gas 说明](https://ethereum.org/developers/docs/gas/)。所有解锁、派生与签名由本地工具执行，不需要商户在 MetaMask 中逐个切换账户。

### 4.4 ETH 怎么测试（含 Tatum 监听）

1. 使用 Ethereum Sepolia，创建独立测试钱包，校验 RPC chain ID，并领取测试 ETH。为订单派生 A、B 两个地址并建立原生转入通知。
2. 固定一份测试报价／费用快照，从发送钱包向 A、B 发送普通 ETH 转账，记录 txid。分别验证已发现、待确认与已确认状态，核对真实回调 HMAC。
3. 确认后比较订单数量、测试服务费和净入账；重复事件不重复入账，主网和法币余额不变。
4. 导入 A、B 到本地工具，填 Sepolia 目标，设置费用上限，逐地址本地签名归集。查询每笔回执和实际 Gas，允许保留合理的费用余量。
5. 再测余额不足以支付 Gas、费用超过上限、pending、重启恢复及目标合约执行失败，不能把失败回执标为归集成功。
6. 使用测试合约向订单地址发内部 ETH 转账，单独验证 Data／trace 和解析路径。**Tatum 官方矩阵不支持 Sepolia 内部交易通知**，不能要求这一项产生主网同款 Webhook；也不能以普通 ETH 转账成功证明内部转入已覆盖。

通过条件：普通 ETH 通知与归集端到端成功；内部调用覆盖单独标明所用证据和缺口。测试网内部查询若不可用，保留待验证，采用本地链及只读主网样例补充；生产开放前仍需完成主网能力核验。

## 5. USDT-ERC20 钱包归集

### 5.1 需要准备

- 订单收款地址对应的 Ethereum 密钥／派生范围。
- 正确网络的官方 USDT 合约及 Ethereum 归集目标，不能仅按代币名称识别。
- 操作者控制的 ETH 手续费账户，准备足够 ETH 支付补充交易以及来源地址的 USDT 转账。

### 5.2 操作步骤

1. 选择 USDT-ERC20，核对 chain ID 和 USDT 合约，查询每个来源地址的 USDT、ETH、nonce 及待处理交易。
2. 填 USDT 归集目标和费用上限。工具逐地址模拟／估算 USDT 转账，不使用写死的代币 Gas 数量。
3. 查看“手续费补充计划”：仅向 ETH 不足的地址补差额，展示补 ETH 本身的费用与预计后续费用；先批准小批量。
4. 在本地解锁并授权 ETH 手续费账户，签名补充交易并广播。每个地址记录已补数量，防止重启后重复补充。
5. 等补 ETH 确认，重新查询各地址余额及费用条件。若行情／Gas 已明显变化，重新预览差额，不盲目进入下一阶段。
6. 本地使用各收款地址的密钥签署 USDT `transfer`，广播并追踪结果；普通自有地址转出本账户 USDT 无需先授权第三方归集合约。
7. 查询成功回执并核对官方合约的实际转账事件，确认目标收到的 USDT 数量；失败项保留并排查，不能只看广播返回 txid。
8. 如需回收剩余 ETH，单独生成计划。回收手续费高于剩余值则保留，不再次转入 ETH 只为清理粉尘。
9. 导出补费、USDT 转出和剩余 ETH 回收的关联交易清单。

### 5.3 成本与异常

一次归集可能包含三类交易：补 ETH、转 USDT、回收 ETH。每类都有相应费用，不能把它们当作平台服务费重复扣商户订单账面余额。

USDT 合约限制、模拟失败、来源 Gas 不足或费用变化时暂停对应地址，展示原因。ETH 补费成功不代表 USDT 归集成功；后续重试从已完成阶段继续，不能重复补费或重复转出。合约身份以 [Tether 官方协议列表](https://tether.to/en/supported-protocols/)核实。

### 5.4 USDT-ERC20 怎么测试（含 Tatum 监听）

1. 使用 Sepolia。准备测试 ETH；本地部署或使用已核对的六位精度测试 ERC20，登记测试合约，命名为模拟 USDT，不使用主网合约地址，也不声称它具有真实 USDT 价值。
2. 创建测试发送钱包、派生收款地址 A、归集目标 C 和 ETH 手续费账户 G。给发送钱包测试币和 Gas；让 A 初始持有 0 ETH，以覆盖补费流程。
3. 为 A 建立实际支持的代币事件通知。通过一笔测试法币订单生成应付数量，向 A 转入模拟 USDT；核对真实回调、合约、事件位置、六位精度及确认后的净入账。
4. 将另一份同名代币转入 A，确认不被目标资产账本接受；普通 ETH 补费也不能被当作 USDT 收入。
5. 本地工具从 G 给 A 补 ETH，确认后签署 A → C 的测试 USDT 转账，核对 `Transfer` 事件和 C 的余额变化。
6. 在“补 ETH 成功、USDT 尚未发送”阶段中断工具并恢复，验证不重复补费；再覆盖 Gas 不足、模拟失败、转出失败和费用上限限制。
7. 按需测试剩余 ETH 回收。将准备、代币归集和回收费用分开记录，不再次扣平台账面余额。

通过条件：代币通知与地址匹配正确、非目标合约不入账、三阶段可恢复、只计一次订单收入。模拟 ERC20 不覆盖所有主网 USDT 行为，主网合约执行差异另做验收。

## 6. USDT-TRC20 钱包归集

### 6.1 需要准备

- TRON 专用钱包及订单地址派生范围。
- TRON 网络的正确 USDT 合约和归集目标。
- 操作者控制的 TRX 手续费账户；按实际需要准备账户激活、带宽、能量或 TRX 燃烧费用。

### 6.2 操作步骤

1. 选择 USDT-TRC20，核对网络与合约，将地址转换为统一格式进行本地匹配。
2. 查询各来源的 USDT、TRX、账户是否激活、能量和带宽，以及是否已有归集任务。
3. 填目标和费用上限，逐地址估算合约执行资源；不将网上流传的固定 TRX 数量作为费用保证。
4. 查看资源准备计划。第一版建议提供“需要时补 TRX 并使用链上资源计费”的基础路径；已有合法委托资源可识别使用，自动质押、租赁与回收资源不是默认已实现功能。
5. 对未激活地址，按工具已验证的 TRON 账户准备流程处理；仅看到 USDT 余额不能证明其已具备签名转出所需状态。显示并确认激活与手续费成本。
6. 本地授权手续费账户，完成必要准备并等待结果确认；重新查询实际资源及 TRX，避免重复补充。
7. 本地用各来源地址密钥签名 USDT 转账，设置合理的 `fee_limit` 并广播。超过资源／费用限制的地址跳过或等待重新确认。
8. 查询固化链交易结果和合约事件，核对目标实际到账；广播成功不等于执行成功。
9. USDT 转出确认后，再独立判断剩余 TRX 是否值得转出；若使用已有资源委托，按委托方规则处理，不承诺工具自动回收。
10. 导出准备、USDT 转出、残余资产处理等交易记录。

### 6.3 常见问题

- **资源不足／执行失败**：失败也可能消耗资源和 TRX；重新查询并估算，不无限重复广播。
- **交易过期**：先确认原交易没有成功，再重新构造并本地签名；签名后的旧交易不能任意修改有效期。
- **补 TRX 成功但 USDT 未转出**：保留阶段记录，从 USDT 转出环节恢复，不重复充值。
- **余额有 USDT，但账户查询异常**：分别核验代币余额和账户状态，不把两者混同。

资源依据见 [TRON 资源模型](https://developers.tron.network/docs/resource-model)，构造、签名、广播及确认见[官方流程](https://developers.tron.network/docs/api-signature-and-broadcast-flow)。本期不使用 Tatum Gas Pump 合约地址或远程签名。

### 6.4 USDT-TRC20 怎么测试（含 Tatum 监听）

1. 优先使用 **Shasta** 做 Tatum Notifications 端到端测试；Nile 不能仅凭 Wallet SDK 支持就当作通知已支持。创建独立测试发送钱包、派生收款地址 A、归集目标 C 和 TRX 手续费账户 G。
2. 按 [TRON 官方测试币指引](https://developers.tron.network/docs/getting-testnet-tokens-on-tron)获取 Shasta 测试 TRX、测试 TRC20，或部署明确的测试合约；登记其地址和精度，模拟 USDT 与主网资产隔离。
3. 查 Tatum 能力列表并给 A 建立可用代币事件订阅。核实 RPC、合约、发送钱包和订阅全部属于 Shasta，再向 A 转测试代币。
4. 检查真实回调 HMAC，并按 TRON 事件格式规范化收发地址；查询成功回执和固化链结果，确认后核对订单服务费与净入账。
5. 分别准备一个未激活且有测试代币的地址、一个已激活但资源不足的地址（测试合约／网络允许时）；先查询状态，工具按实测情况生成账户准备与补 TRX 计划，不能假定转入测试代币一定会激活账户。
6. 本地从 G 完成必要准备，重新查询资源，再从各来源签名转出到 C。核对 `fee_limit`、真实执行结果和目标数量，不能只用广播成功判定。
7. 在补 TRX 后中断并恢复，验证不重复补费；覆盖资源不足、交易过期、合约执行失败及剩余 TRX 处理。
8. Shasta 停链／接口不可用时登记环境阻塞。Nile 可用于工具补充测试，但不能替代 Shasta 通知结果或证明 Tatum Nile 监听可用。

通过条件：收到 Shasta 真实代币通知、固化链核验及净额入账正确、账户与资源准备可恢复、归集不重复计收入；主网资源价格和 USDT 合约差异仍需受控验收。

## 7. 恢复、交接与验收

### 7.1 恢复钱包

使用本地备份和原派生方案恢复钱包，导入平台完整的地址范围和指纹，重新派生并核对已知收款地址。恢复时不能只扫描默认前几个地址；收款很多但大量订单未付款时，需要覆盖连续空地址区间。

保留平台地址清单、配置版本和本地任务记录的备份；它们不能替代私钥恢复资料。平台拿不到私钥，无法替操作者恢复丢失的签名能力。

### 7.2 与平台账务对照

- 归集只是链上转移，不再次给订单增加收入，不自动扣账面本金。
- 本地钱包实收包含账面已计提但尚未线下缴纳的服务费，不要以净入账数量推断钱包实际余额。
- 归集记录不自动变成取款凭证。只有明确用于某笔取款且经平台审核核验的转账，才核销对应占用和余额。
- 不把密钥、钱包文件或解锁密码放入客服材料；排查只提交必要交易哈希和脱敏任务信息。

### 7.3 教程转为正式操作手册的门槛

每种资产均需补齐：工具版本和下载签名、实际界面截图、主网／测试网配置、兼容钱包资料格式、恢复验证、首次小额归集、批量执行、费用不足与交易卡住处理、重启后不重复转出验证。ETH／TRON 主网行为、Tatum 测试接口与主网差异分别记录。

逐链测试须遵守[方案第 13.1 节的能力矩阵、通知联调和证据要求](../docs/blockchain-payment-plan.md)。测试结果至少区分：真实 Tatum 回调通过、RPC 查询通过、本地故障测试通过和未覆盖；不能用手工模拟回调或本地链成功替代真实供应商监听。测试币无现金价值，但节点请求、通知、部署测试合约等可能消耗 Tatum 额度或测试 Gas；不要误认为测试链接口无限免费。

本文只提供操作设计，不表示已执行真实归集、购买 Tatum 套餐、部署节点或开通任何签名服务。
