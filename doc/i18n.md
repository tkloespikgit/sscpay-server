# 多语言支持说明

## 现状

后台所有面向用户的界面文字（Resource 表单/表格标签、Section 标题、
按钮文案、通知提示、仪表盘统计卡片、图表标题、付款链接邮件、Telegram
通知消息）都已经从硬编码的中文改成走 Laravel 的 `__('admin.xxx.yyy')`
翻译函数，指向 `lang/{locale}/admin.php` 这个语言文件。

**英文（`lang/en/admin.php`）是基准语言包**，中文（`lang/zh_CN/admin.php`）
是从原来硬编码的文案原样翻译过去的，两份文件的 key 结构逐字一致
（已通过脚本校验：两边各 16 个顶层分组，key 完全对应）。

## 怎么加一个新语言

1. 复制整个 `lang/en/admin.php` 到 `lang/{你的语言代码}/admin.php`
   （比如 `lang/fr/admin.php`、`lang/ja/admin.php`）。
2. 只翻译**值**（等号右边的字符串），**不要改 key**（等号左边的部分）
   ——key 是代码里引用的标识符，改了 key 会导致代码里 `__('admin.xxx')`
   找不到对应的翻译，界面会显示 `admin.xxx` 这种原始 key 字符串。
3. `.env` 里设置：
   ```env
   APP_LOCALE=fr
   ```
4. 清一下缓存：
   ```bash
   php artisan config:clear
   php artisan view:clear
   ```
5. 刷新页面，整个后台应该已经是新语言了。

## 用户可以自己切换语言吗？

现在**没有**做"用户在界面上自选语言"这个功能——语言是通过 `.env` 里
`APP_LOCALE` 这个全局配置决定的，一次部署只有一种语言，所有用户看到
的是同一个语言。如果需要"每个用户自己选语言"，需要额外做：
- 在 `users` 表加一个 `locale` 字段
- 在中间件里根据登录用户的 `locale` 调用 `App::setLocale($user->locale)`
- 后台加一个语言切换的下拉框

这个需求文档里没有提到，所以没有实现，如果需要请告诉我。

## ⚠️ 三处这次没有覆盖到的地方，需要你知道

### 1. Filament 自身的界面文字不受这份语言包控制

按钮上的 "Create"/"Edit"/"Save"、表格分页的 "Showing 1 to 10 of 50
results"、通知提示 "Saved successfully" 这些是 **Filament 框架自己
内置的界面文案**，来自 Filament 包自带的语言文件（`vendor/filament/...`
里的翻译），不是我们业务代码里写的字符串，所以这份 `lang/{locale}/admin.php`
语言包管不到它们。

Filament 官方对多语言的支持方式是：Filament 包本身内置了一部分语言的
翻译（具体覆盖哪些语言取决于你安装的 Filament 版本），如果你要用的语言
Filament 没有自带，需要额外找社区维护的 Filament 语言包，或者自己
`php artisan vendor:publish --tag=filament-translations` 发布出来
翻译。**这部分我没有处理**，因为改动范围在 Filament 包内部，不属于
这次"改我们自己写的代码"的范围。

### 2. `system_configs` 表里的 `description` 字段是数据，不是代码字符串

`SystemConfigSeeder` 往数据库里写入配置项时，`description` 列
（比如"汇率转换汇损百分比（%）"这段说明文字）是**存在数据库里的**，
不是 PHP 代码里的字符串，这份基于语言文件的机制覆盖不到它。

如果需要这部分也支持多语言，需要额外做一张 `config_translations` 表
（或者用 `spatie/laravel-translatable` 这类包给 `system_configs.description`
字段做多语言字段），现在没有实现，无论 `APP_LOCALE` 是什么，这里显示
的都是 `SystemConfigSeeder` 里写入时的原始语言（中文）。

### 3. 付款邮件 / Telegram 通知跟着系统全局语言走，不是按商户各自的语言

`PaymentLinkMail`（发给终端客户的付款邮件）和 `SendTelegramNotification`
（发给商户运营团队的 Telegram 消息）现在也翻译成走 `__()`，但翻译用的
是**当前系统的全局 `APP_LOCALE`**，不是"这个商户/这个客户偏好用什么语言"。

如果你们服务多个国家的商户、每个商户希望收到自己语言的通知，需要：
- `merchants` 表加一个 `locale` 字段
- 发送邮件/Telegram 消息前用 `App::setLocale($merchant->locale)` 临时切换
  （发送完记得 `App::setLocale(config('app.locale'))` 切回来，否则会
  污染后续同一个请求生命周期里的其他逻辑）

这个需求文档里也没有提到，同样是可以做但现在没做的部分。
