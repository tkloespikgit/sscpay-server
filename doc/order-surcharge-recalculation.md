# 历史订单汇损补算

此前漏配换汇汇损时，使用 `orders:recalculate-surcharge` 按商户修复订单快照。先在后台保存正确的 `exchange.surcharge_type` 及对应的百分比或固定值；命令直接读取数据库中的最新配置，不使用配置缓存，也不抓取当前市场汇率。

## 使用

以商户 ID `12` 为例（也支持完整商户名称；重名时必须使用 ID）：

```bash
php artisan orders:recalculate-surcharge 12
php artisan orders:recalculate-surcharge 12 --apply
```

默认仅预览；`--apply` 才写订单。可按订单创建日期缩小范围，起止日期都包含当天，按系统时区解释：

```bash
php artisan orders:recalculate-surcharge 12 --from=2026-10-01 --to=2026-10-13 --details
php artisan orders:recalculate-surcharge 12 --from=2026-10-01 --to=2026-10-13 --apply
```

`--details` 在终端输出逐单结果；每次运行都会新建 JSON 审计报告，默认位置为 `storage/app/private/order-surcharge-reports/{uuid}.json`，也可以传 `--report=/absolute/path/new-report.json`。命令不会覆盖已有报告。报告包括此次配置、过滤条件、逐单修改前后快照、跳过原因、汇总和需补算统计的日期。

## 处理范围

- 明确限定所传商户，排除软删除订单、USD 订单和非 USD 结算订单。
- 仅处理 `paid`、`shipped`、`completed`，且具有唯一 `order_paid:{id}` 自动入账流水的订单。真正需要变更时还要求原流水金额与修改前 `settlement_amount` 一致，否则列为需人工核对。
- 跳过退款、拒付、争议状态，存在退款记录、任何争议历史、退款金额或其他关联资金流水的订单。即便争议已关闭，也不在此命令中重写相关资金口径。未支付或缺少入账流水的订单不计入手工调账参考金额。
- 默认只修复原汇损各金额/百分比均为零且实际汇率等于原始汇率的订单；`--include-existing` 才允许处理已有汇损快照。该选项仍受其他检查约束，不会绕过账务异常。
- 非法配置、无效日期、商户不存在/重名会报错；异常汇率、快照缺失、金额超出数据库精度或新金额不足以覆盖原手续费的订单会列出跳过原因。

重复执行时不累加汇损：始终从原始市场汇率重新算。已经修好的订单默认会跳过，显式 `--include-existing` 且结果相同则标为未变化；两种情况下本次差额均为零。若修复过后还要更换配置，因原入账流水不可变，与订单快照不符的单据会跳过，需结合先前人工调账单独核对。

## 金额口径

保留每笔订单的 `original_exchange_rate`，只叠加本次最新汇损配置：

```text
百分比：实际汇率 = 原始市场汇率 × (1 + 汇损百分比 / 100)
固定值：实际汇率 = 原始市场汇率 + 固定汇损值
无汇损金额 = 当前订单 amount × 原始市场汇率
含汇损金额 = 当前订单 amount × 新实际汇率
新净入账 = 含汇损金额 - 原 fee_percent_amount - 原 fee_fixed_amount
```

金额使用十进制字符串和 bcmath。百分比配置最多 4 位小数、固定值最多 6 位小数；实际汇率保留 6 位，金额保留 2 位并沿用现有下单的截断口径。正汇损上浮汇率，负汇损下浮汇率。USD 订单不收换汇汇损。

本次保留历史支付手续费金额，**不使用渠道当前费率重新收手续费**。订单只保存了当时的手续费金额，未保存原百分比费率，不能从截断后的金额精确还原费率。原币种金额、商品、自动折扣、原始市场汇率、渠道和远端订单均不改；更新实际汇率、`surcharge_*`、各订单折算字段和 `settlement_amount`。商品匹配的 USD 商品单价不会乘新汇率重写。

输出两个不同的差额：

1. **含汇损 − 无汇损**：新配置相对无汇损基准的总影响。
2. **本次净入账变化**：新 `settlement_amount` − 修改前 `settlement_amount`，作为此次手工调账参考。正数增加余额，负数扣减余额。

例如原折算 `110.00 USD`、原手续费合计 `3.60 USD`，新汇损为 `-2%`：新折算 `107.80 USD`，净入账从 `106.40` 变为 `104.20`，此次参考调整为 `-2.20 USD`。有历史汇损时，这两个差额可能不同；金额逐项截断也可能使二者与 `surcharge_fee` 相差一美分，应以报告计算结果核对。

## 写入与后续操作

命令不修改余额、冻结余额和原有资金台账，不触发网关、邮件、回调、广告转化或订单状态事件。`--apply` 在单个数据库事务内先锁商户，再分批读取并锁订单，重新检查资格；写库或报告落盘失败会整批回滚，失败报告标记为 `failed`。整批执行会持有商户锁，宜选择该商户资金操作较少的时段。

仅根据成功完成的 `applied` 报告做一次人工调账，预览或失败报告不能当成已修改订单的凭据。使用后台现有资金调整入口记账并在备注中保留报告路径；原自动入账流水保留原值，报告记录本次订单快照纠正。若进程异常中断，应先核对数据库与运行结果，不能仅凭一个报告文件判定已提交。

修改成交额后，风控读取到新订单值；历史 `order_daily_stats` 不会自动重建。命令会按各单的 `paid_at`（空时回退 `created_at`）列出受影响日期及以下补算命令：

```bash
php artisan order-stats:aggregate --date=2026-10-01
```

仅重算实际报告列出的日期。该统计命令按整日重建所有商户的统计桶，沿用现有统计口径。
